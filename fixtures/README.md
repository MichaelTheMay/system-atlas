# Fixtures

Small, deterministic systems used to test Atlas. Atlas analysis must never modify, install or
execute them; tests that execute `research-demo` do so on a temporary copy; tests assert their content hash is unchanged after registration and scanning.

| Fixture | Shape | Used by |
|---|---|---|
| `ts-web-service` | TS monorepo: React UI, Fastify API, BullMQ worker, Redis queue, Postgres tables, Docker Compose | A03-A07, Phase 1 acceptance |
| `py-cli-api` | Python package: FastAPI API, argparse CLI, export job, SQLite store | A03-A07, Phase 1 acceptance |
| `elixir-unsupported` | Elixir service with no Atlas analyzer | A03 coverage gaps |
| `research-demo` | §18 demo: web page, API + queue, worker with two tools writing JSON/PNG/HTML | Phase 2 (`atlas run`, browser capture, Outputs & Audit) |

Hand-authored expected graphs (`expected.json`) are added with the analyzers in A04 and are
written independently of extractor output (plan §16).

## otlp/

Hand-written OTLP/JSON trace exports for the importer (I03), never generated by Atlas:

- `agent-trace.json` holds two traces, the second with base64 IDs. The agent trace covers:
  - GenAI tool spans;
  - an ERROR span with an exception event;
  - a client span with a link and a bytes attribute;
  - a span without a start time;
  - an orphan span whose parent is not in the file;
  - an unfinished span.
- `agent-trace-late.jsonl` delivers one late span of the agent trace and a duplicate of its root, one JSON document per line.
